# Cloudflare Workers: Telegram webhook + D1

Отдельная серверная реализация бота на JavaScript для Workers Free.
Python-версия в корне продолжает поддерживать локальный запуск.
Cloudflare Containers не используются. Бесплатные квоты общие для аккаунта;
отсутствие расходов не означает гарантии доступности или отсутствия лимитов.

## Устройство

- Webhook `/telegram` проверяет секрет Telegram, ID владельца и приватный чат.
- Команды, задания, сводки, настройки и диалоги управления расписанием сохраняются.
- D1 хранит состояние и очередь уведомлений. Lease с fencing предотвращает одновременные записи cron и webhook.
- Cron запускается раз в минуту. Каждые 15 минут начинается проход Canvas,
  который обновляет по одному курсу в минуту; пять курсов обрабатываются примерно за пять минут.
  При ошибке курс повторяется, сохранённые задания не помечаются удалёнными.
- Отправка уведомлений повторяется после ошибки; до отправки проверяется актуальность.
  Ключи дедлайнов включают дату дедлайна, поэтому перенос не блокирует новые напоминания.
- При неоднозначном сетевом сбое между доставкой Telegram и сохранением результата
  возможен дубль: Telegram не предоставляет ключ идемпотентности для sendMessage.
- Баннеры доступны через Workers Static Assets, Telegram file_id переносится из SQLite.
- Описания заданий сохраняются на языке преподавателя; ИИ и чтения вложений нет.
- Настройки времени и расчёты используют Asia/Tashkent (UTC+5).

## Тесты и сборка

Тесты требуют Node.js с `node:sqlite` (например Node.js 24).

```sh
pnpm install
node --test
pnpm exec wrangler deploy --dry-run
```

## Развёртывание

1. Авторизовать Wrangler для своего Cloudflare-аккаунта.
2. Создать отдельную D1: `wrangler d1 create goshapa-student-assistant`.
3. Записать полученный database_id в `wrangler.jsonc`.
4. Выполнить `wrangler d1 execute goshapa-student-assistant --remote --file=schema.sql`.
5. Создать приватный снимок, запустив `python cloudflare/export_state.py` из корня проекта.
   `private/` исключён из Git. Экспорт предназначен для первоначального переноса,
   повторный импорт поверх работающего облака заменит его текущее состояние.
6. Импортировать `private/import.sql` через `wrangler d1 execute` в новую базу.
7. Задать секреты `BOT_TOKEN`, `OWNER_TELEGRAM_ID`, `CANVAS_ACCESS_TOKEN`, `WEBHOOK_SECRET`
   через Wrangler secret bulk (JSON-файл в `private/`). Никогда не коммитить секреты.
8. Опубликовать Worker с `ENABLED=false`, проверить `/health`.
9. Остановить локальный бот, обновить снимок и импортировать окончательное состояние.
10. Записать `PUBLIC_URL` и `ENABLED=true`, развернуть Worker.
11. В Telegram setWebhook указать `PUBLIC_URL/telegram`, `secret_token=WEBHOOK_SECRET`,
    `allowed_updates=["message","callback_query"]`, `max_connections=1`.
12. Проверить getWebhookInfo, живую команду в Telegram и выполнение cron.
    Изменения Cron Triggers могут распространяться до 15 минут.

## Откат

Сначала отключить Worker (`ENABLED=false`) и удалить webhook Telegram.
Только затем запускать локальную Python-версию. Изменения, сделанные в облаке,
нужно отдельно перенести в локальную SQLite: автоматического обратного импорта нет.

`/health` не раскрывает задания, токены или настройки. Других служебных HTTP-маршрутов нет.
В журналах записывается категория ошибки, а не URL Telegram с токеном или тело Canvas.
